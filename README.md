# Бот статусов заказов для кухонной фабрики

Telegram-бот под ситуацию производителя кухон на заказ: фабрика, три шоурума, дилеры в пяти городах, заказ проходит через замер → дизайн → производство → монтаж, и на каждом стыке теряется информация.

Бот не заменяет CRM. Это первый рабочий контур управления, который можно запустить за день, пока данные в таблицах ещё не приведены в порядок:

| Проблема из кейса | Что делает бот |
|---|---|
| Срок срывается у каждого третьего заказа, узнают об этом поздно | Каждое утро ответственный отмечает статус заказа. «Всё по плану» — одна кнопка, «риск» или «срыв» — три вопроса: что мешает, прогноз, следующий шаг. Бот сам замечает отставание от графика: например, до монтажа 11 дней, а заказ всё ещё на дизайне |
| Информация теряется на стыках | Заказ переходит на следующую стадию только по чек-листу передачи (лист замера подписан, предоплата получена, комплектность сверена…). Новый ответственный получает и заказ, и то, что ему передали |
| Дилеры звонят собственнику | Дилер видит статус своих заказов и задаёт вопрос ответственному. Нет ответа за 2 часа — вопрос автоматически уходит руководителю |
| Планёрка раз в неделю без цифр | Сводка руководителю: что горит и почему, кто молчит больше суток, сколько плановой маржи в заказах под риском, какие решения ждут |
| Решения размыты | Плановую дату бот сам не меняет. Если прогноз позже плана, руководитель выбирает: перенести дату и предупредить клиента — или держать план |

## Как посмотреть за 3 минуты

1. Откройте бота в Telegram и нажмите **Start** → выберите роль **Ольга — руководитель**.
2. **⏰ Утренний опрос** — бот разошлёт сотрудникам их заказы. В демо-режиме все сообщения придут вам с пометкой, кому они на самом деле, и вы сможете ответить за каждого.
3. Под заказом **K-1042** нажмите **⛔ Срыв срока**. Попробуйте ответить «нет» — бот не примет отговорку. Потом заполните по-настоящему и выберите прогноз позже плана.
4. Откройте **📊 Сводка**: K-1042 стал красным и ждёт вашего решения. Решите кнопкой.
5. Под **K-1048** нажмите **➡️ Передать: Производство** и попробуйте передать заказ, не отметив весь чек-лист.
6. **👥 Сменить роль** → дилер **«Дом кухни», Киров** → **📋 Мои заказы** → задайте вопрос по K-1057.
7. **📤 Выгрузка** — реестр заказов и журнал событий в CSV, открывается в Excel.

Демо-данные — 8 заказов с разными проблемами: просрочка, нет ответственного, блокер, молчащий сотрудник. `/reset` возвращает их в исходное состояние.

## Запуск в Docker

```bash
cp .env.example .env        # и вставьте токен от @BotFather в TELEGRAM_BOT_TOKEN
docker compose up -d --build
docker compose logs -f
```

База SQLite хранится в томе `bot-data` и переживает перезапуск контейнера. Токен лежит только в `.env`: этот файл исключён и из git, и из образа.

Без Docker: `python3 bot.py` (нужен Python 3.9+, внешних зависимостей нет).

## Настройки (`.env`)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `DEMO_MODE` | `1` | Роль выбирается кнопкой, сообщения неподключённым сотрудникам приходят в демо-чат |
| `SCHEDULE` | `0` в демо, `1` в работе | Автоматические рассылки: опрос в `PING_AT`, сводка в `DIGEST_AT`, напоминание молчащим в `REMIND_AT` |
| `ESCALATE_MINUTES` | `120` | Через сколько минут неотвеченный вопрос дилера уходит руководителю |
| `BOT_TZ` | `Asia/Yekaterinburg` | Часовой пояс фабрики |

## Правила риска

Правила простые и объяснимые: каждая причина выводится в карточке, чтобы было видно не только цвет, но и почему он такой.

- 🔴 **Критично** — монтаж просрочен; нет ответственного; прогноз позже плановой даты.
- 🟡 **Внимание** — есть блокер; нет статуса больше суток; заказ отстаёт от графика (до монтажа меньше дней, чем нужно на оставшиеся стадии: замер — 21, дизайн — 14, производство — 3).
- 🟢 **По плану** — всё остальное.

Пороги задаются в начале `core.py` и настраиваются под реальные сроки фабрики.

## Устройство

- `core.py` — данные (SQLite), правила риска, проверка ответов, передача по чек-листу. Всё, что меняет заказ, проходит через функции `report_ok`, `report_problem`, `decide`, `handoff`, `assign` и записывается в журнал событий.
- `bot.py` — Telegram: диалоги, кнопки, сводка, выгрузка, расписание. Работает на стандартной библиотеке Python через long polling, поэтому не нужен ни публичный адрес, ни вебхук.
- `tests/` — 25 тестов: правила и проверки в `test_core.py`, сквозные сценарии через поддельный Telegram API в `test_scenario.py`.

```bash
python3 -m unittest discover -s tests -v
```
